# OSTEP Ch 7 — Scheduling: Introduction 정리

여러 작업을 **어떤 순서/타이밍으로 실행할지** 정하는 정책, 그리고 정책을 **어떻게 평가할지(지표)**.

---

## 단순화 가정 (하나씩 벗겨감)

1. 모든 작업 길이 같음 → SJF에서 벗김
2. 모두 동시 도착 → STCF에서 벗김
3. 시작하면 끝까지(비선점) → STCF/RR에서 벗김
4. CPU만 씀(I/O 없음) → overlap에서 벗김
5. **실행 시간 미리 앎** → 벗기면 SJF/STCF 불가 → MLFQ(Ch8)

## 세 지표

- **응답시간(response)** = 처음 실행 시각 − 도착 시각. ("첫 반응까지")
- **반환시간(turnaround)** = 완료 시각 − 도착 시각. ("끝까지")
- **대기시간(wait)** = Ready였지만 실행 못 한 총 시간 = 반환 − 자기 실행시간.

---

## 정책들

### FIFO (First In First Out)
- 온 순서대로, 끝까지.
- **convoy effect(호위 효과)**: 짧은 작업이 앞의 긴 작업 뒤에 갇힘. (A=100,B=10,C=10 → 평균 반환 110)
- 비선점이라 **응답 = 대기**.

### SJF (Shortest Job First)
- 짧은 작업 먼저 (비선점).
- **동시 도착 시 평균 반환 최적.** (convoy 해결)
- 약점: 긴 작업이 이미 돌고 있으면, 늦게 온 짧은 작업이 **못 끼어듦**(비선점). (A=100@0 도는 중 B,C@10 도착 → 평균 반환 103.3)

### STCF (Shortest Time-to-Completion First) = 선점형 SJF
- 새 작업 도착 시마다 **잔여시간 최단**을 실행 (선점).
- **반환시간 최적** (도착 시점 달라도). 위 예 → 평균 50.
- 약점: **응답시간 나쁨** (짧은 걸 끝까지 몰아서 뒤 작업 첫 반응 늦음).
- 치명적 전제: **실행시간을 알아야** 함.

### RR (Round Robin)
- 타임슬라이스(quantum)씩 번갈아 순환.
- **응답시간 좋음** (다들 금방 첫 반응).
- 약점: **반환시간 나쁨** (다 조금씩 미뤄짐). 비선점 아니라 **응답 ≠ 대기**.
- 슬라이스 크기 = 다이얼:
  ```
  q 작음  ──────────────→  q 큼(≥작업길이)
  응답 좋음                응답 나쁨(=FIFO)
  반환 나쁨                반환 좋음(=FIFO)
  문맥교환 많음(오버헤드↑)   문맥교환 없음
  ```
  - q가 작업 길이보다 크거나 같으면 **RR = FIFO** (선점 안 일어남).
  - q 너무 작으면 **문맥교환 비용(Ch6 실측 1.2μs)**이 쌓여 오버헤드 폭증.

## 핵심 긴장: 반환 ↔ 응답 트레이드오프

| 정책 | 반환 | 응답 | 한계 |
|------|------|------|------|
| FIFO | ❌ convoy | - | 긴 작업 앞이면 최악 |
| SJF | 동시도착 최적 | 나쁨 | 늦게 온 짧은 작업 못 끼움 |
| STCF | ⭐ 최적 | ❌ | 실행시간 알아야 |
| RR | ❌ | ⭐ | q vs 문맥교환 비용 |

- **반환 최적(STCF)과 응답 최적(RR)을 동시에 만족하는 정책은 없다.** 한쪽 얻으면 한쪽 잃음.
- 배치 작업 → 반환 중요(STCF류), 인터랙티브 → 응답 중요(RR류).

## I/O 다루기 (가정 4 벗김)

- I/O로 blocked된 시간 = CPU 노는 시간 → **다른 작업으로 overlap.**
- I/O 내는 작업을 **CPU 버스트 단위로 쪼개** 취급 → 각 조각이 짧아 우선권 받고 빨리 돌다 I/O로 빠짐 → I/O(디바이스)와 CPU(다른 작업)가 동시에 바쁨.
- process-run.py의 IMMEDIATE가 CPU 100% 찍던 원리.

## MLFQ로 가는 다리 (가정 5 벗김)

- SJF/STCF는 **실행시간을 안다**는 전제 → 현실에선 **모름**(입력·분기·루프에 따라 천차만별).
- 해결 실마리: **미래를 예측하지 말고 과거를 관찰.** 지금까지 CPU를 많이 썼나/I/O를 자주 했나로 미래를 추측.
- → **MLFQ (Multi-Level Feedback Queue, Ch 8)**: 과거 행동을 피드백 삼아 우선순위 조정.

## 숙제 (scheduler.py)

FIFO/SJF/RR에 대해 응답·반환·대기 계산. `-c` 없이 예측 → `-c`로 검증.

```bash
./scheduler.py -l 1,4,7 -p FIFO          # 작업 길이 직접 지정
./scheduler.py -l 7,4,1 -p SJF           # SJF는 짧은 것부터 (Job번호≠실행순서 주의)
./scheduler.py -l 5,5,5 -p RR -q 1       # 타임슬라이스 지정
./scheduler.py -p SJF -j 3 -s 100        # 랜덤(시드로 무한 문제 생성)
```

**계산 팁:**
- 실행 구간을 시각별로 적으면 쉬움. RR은 시각별 실행 Job을 나열:
  ```
  시각: 0 1 2 3 4 ...   (5,5,5, q=1)
  Job:  0 1 2 0 1 ...
  각 Job이 5번째 실행되는 시각 = 끝나기 직전
  ```
- **반환 = 완료 − 도착**, 늦게 온 작업은 **도착 빼기** 잊지 말 것.
- FIFO/SJF(비선점): **응답 = 대기**. RR(선점): 응답 ≠ 대기.

**실측 결과 (5,5,5):**
| | 평균 응답 | 평균 반환 |
|--|------|------|
| SJF/FIFO | 5 | 10 |
| RR (q=1) | **1** | **14** |
| RR (q=2) | 2 | 14 |
| RR (q=5) | 5 | 10 | ← FIFO와 동일 |

→ q를 키울수록 응답↑, 극단(q≥길이)에서 RR=FIFO. 트레이드오프를 다이얼로 확인.
